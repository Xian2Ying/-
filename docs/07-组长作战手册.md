## 零、先说实话：这局的真实难度

| 现实 | 含义 |
|---|---|
| 3 人，全是学生，要上课 | 实际有效工时约 **60–90 小时**（4 周合计，已打 6 折） |
| 零技术经验 | 学工具、踩坑、返工会额外吃掉 30%–40% 时间 |
| 只剩 **29 天**（10-30 → 11-28） | 扣掉 PPT/视频/测试，**核心开发只有 20–45 小时** |
| 硬交付：可访问链接 | 链接打不开 = 直接出局，比做得粗糙严重得多 |

**所以目标必须调整**：

> ❌ 不是「做一个惊艳的游戏」
> ✅ 而是「稳稳交出一个**完整、能玩、讲得清**的作品」

惊艳是加分项，完整是及格线。**先拿及格线，有余力再冲。**

## 一、好在有一件事站在你们这边

**编码工作可以大量交给 AI**——这正是"用 AI 解决问题"的命题精神，不是作弊。

| 你们负责（AI 做不了） | AI（我）负责 |
|---|---|
| 想清楚要做什么、为什么做 | 把需求翻译成可运行代码 |
| 准备真实内容（词库、题目、文案） | 写页面结构、样式、交互逻辑 |
| 反复体验、挑错、提改进意见 | 修 bug、调布局、做适配 |
| 决定做什么、不做什么（守范围） | 生成美术素材、PPT、视频脚本 |

**结论**：「不会写代码」这个短板，是 AI 最能补的部分。真正会拖垮项目的是**范围失控**和**没人验收**——这两件事只能你来管。

## 二、因为零经验，方案再下调三档

### 下调 1 · 技术栈降到最简

| 原计划 | 调整后 |
|---|---|
| 多文件 + ES Module + 目录结构 | **第一版：单个 `index.html`**（内联 CSS/JS），双击就能看效果 |
| 拆分 `core/views/data` 多层目录 | 跑通后**再拆**，拆分是低风险重构 |

**理由**：零经验最怕"改了没反应"和"不知道错在哪"。单文件双击即开，反馈最快、出错最好定位。
**底线**：技术债务可以后面还，看不见效果不能忍。

### 下调 2 · AI 口语 NPC 降为「选做加分项」

| 原计划 | 调整后 |
|---|---|
| P0 必做（演示版） | **P1 选做**，11-20 前没搞定就砍掉，只保留固定脚本演示 |

**理由**：接 API、处理 key、应对网络失败，是全项目最容易翻车的一环，而它不影响"游戏能不能玩"。
**原则**：**任何威胁"链接能打开"的功能，优先级一律往后排。**

### 下调 3 · 开发冻结提前到 11-24

| 原计划 | 调整后 |
|---|---|
| 开发到 11-28 | **11-24 冻结代码**，只修致命 bug，不再加功能 |

**理由**：留 4 天给 PPT、宣发视频、以及"一定会出现"的意外。零经验团队的意外不会只有一次。

## 四、三人分工（无经验版，按"不写代码"重新设计）

| 角色 | 人 | 干什么 | 交付物 | 不需要会什么 |
|---|---|---|---|---|
| **内容官** | 队友 A | 找词、写释义/例句、出题、校对 | `src/data/*.json` 的内容表（先用 Excel/表格写，我转 JSON） | 不用碰代码 |
| **体验官** | 队友 B | 在手机上反复玩，记录 bug 和"哪里不爽" | bug 清单 + 改进建议 | 不用写代码；只需会"打开网页+截图" |
| **组长（你）** | 你 | 拍板、守范围、验收、写说明、对外沟通 | PRD、作品说明、PPT 内容、演讲 | 不用写代码；要会"说不" |

**注意**：队友 B 原本设想是"技术担当"，但既然零经验，把他的角色从"写代码"改成"找问题"更现实——**一个零经验的人写代码是风险，找 bug 是资产**。代码由我来写。

## 五、工作流：每天怎么和 AI 协作

### 单次任务的正确姿势（给三个人统一话术）

```
1. 说清楚背景：我们在做 word-quest，一个像素闯关英语学习 H5
2. 说清楚位置：问题在【关卡地图 / 答题页 / 结算页 / 错题本】
3. 说清楚现象：我点了 X，出现了 Y（贴截图）
4. 说清楚期望：我本来以为会 Z
5. 加上约束：只改这一个地方，不要动其他功能
```

❌ 别说"做不好，你看着改"——AI 只能瞎猜
❌ 别说"优化一下体验"——无法验收

### 提交代码的极简三步（给队友 B）

```bash
git pull                              # 每天开工前先拉
# ...改动文件...
git add -A && git commit -m "fix: 修了XX问题"
git push
```

记不住就问我，我会给确切命令。

## 六、验收标准：怎么算"做完了"

**必须可数，不能靠感觉。** 第一版验收清单：

- [ ] 3 个关卡，每关 10 题，共 30 题可作答
- [ ] 100 个词，每个词有：拼写、音标、中文释义、例句
- [ ] 3 种题型（看词选义 / 听音选词 / 拼写填空）都能正常作答和判分
- [ ] 错题本：能看到错过的词，能一键重练
- [ ] 进度存档：关掉网页再打开，进度还在
- [ ] 手机端：Chrome + Safari 打开无错位、按钮点得动
- [ ] PC 端：Chrome 打开自动变宽屏布局，键盘可操作
- [ ] 断网：第 1 关仍可玩
- [ ] **链接在 3 台不同设备上都能打开**（最硬的一条）

## 七、风险清单与兜底

| 风险 | 概率 | 兜底方案 |
|---|---|---|
| 做不完 3 关 | 中 | 砍到 2 关，保证前 2 关打磨到位 |
| 拼写题太难做 | 中 | 砍到 2 种题型 |
| AI NPC 接不上 | 中 | 固定脚本演示；游戏本体不受影响 |
| 云端同步搞不定 | 高（无后端经验） | **存档码兜底**：导出文本码/JSON，另一端导入 |
| PC 端来不及 | 中 | 移动端响应式在 PC 上本来就能打开，只是不优化 |
| 队友中途掉队 | 中 | 内容官的 JSON 是核心资产，提前锁定；组长兜底 |
| 链接失效 | 低 | 提交前 3 天起每天点一次，截图留证 |

## 八、组长每日 5 分钟检查清单

每天花 5 分钟过一遍：

1. **今天谁做了什么？**（一句话，发群里）
2. **有没有人卡住超过 1 天？**（卡住就立刻分给我或换人）
3. **有没有新增需求？**（新增一律记入 P1/P2，第一版不加）
4. **链接还能打开吗？**（点一次）
5. **距离下一个门禁还有几天？**（倒计时）

**组长最大的责任不是写代码，是守范围和保证能交。**
每次有人想加功能，你的第一反应应该是："这个进 P1 清单，第一版不做。"
