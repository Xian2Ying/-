# 04 · 方案选型决策：对话式 AI vs 小游戏

> 状态：**已拍板（推荐版）** · 日期：2026-10-30 · 决策人：队长（待队友确认后回填 `docs/02`）
> 优先级原则：**完整度与内容 > 创新**

---

## 一、结论（先看这个）

**选择：小游戏为主载体。**

更准确地说——

> 做一个**像素闯关风英语学习小游戏**，把「对话式 AI」降级为游戏内的一个模块（NPC 口语陪练），
> 而不是做一个独立的对话式 AI 产品。

这不是把两个方案并列，而是定主次：**游戏是壳，AI 是核**，两条线都保留，但以游戏为对外呈现的主体。

---

## 二、为什么不做独立的对话式 AI

| 维度 | 对话式 AI 的问题 |
|---|---|
| **完整度可证明** | ❌ 致命。对话产品的边界是开放的，界面永远是「输入框 + 一段文字」。做 3 个功能和 10 个功能长得一样，评委看不出完成度，无法给出「做得完整」的评价 |
| **内容可展示量** | 内容藏在提示词里，评委看不见、摸不着，作品说明里也没法截图举证 |
| **撞题风险** | 大赛要求「依托 WorkBuddy 开发 AI 智能体，输出网页或应用」，做对话机器人是最省事的路径 → 预计大量队伍撞题 |
| **现场演示** | 评委打开 → 问两句 → 得到文字 → 关掉，停留 30 秒。游戏能让评委停留 3–5 分钟，停留时间≈印象分 |
| **抗风险** | ⚠️ 100% 依赖大模型 API。评审时 key 过期 / 额度耗尽 / 网络波动 → 链接打不开 = 0 分（而「可访问链接」是硬性交付项） |
| **创新落点** | 创新只能体现在提示词，评委看不见、没法横向比较 |

**对话式 AI 只赢两项**：最贴合「AI 智能体」命题、最容易落地。
但这两项正是本次愿意让渡的部分（完整度与内容优先）。

---

## 三、为什么小游戏赢

| 维度 | 小游戏的表现 |
|---|---|
| **完整度可证明** | 有明确终点：3 关 × 100 词 × 3 种题型 + 结算页 + 错题本 + 进度存档。做完没做完一眼可见 |
| **内容可展示量** | 词库、题目、知识卡、错题本、成就系统——全是「看得见的内容物」，作品说明里能直接截图举证 |
| **差异化** | 像素闯关 + 艾宾浩斯复习调度 + AI 口语陪练的组合，市面上少见，不容易撞题 |
| **现场演示** | 评委愿意玩。点关卡、做题、看金币跳动、看结算——体验曲线完整 |
| **抗风险** | 核心关卡逻辑跑在本地，AI 接口挂了游戏照样能玩（降级容错，这是代差级优势） |
| **创新落点** | 像素美术、Boss 关、连击、记忆曲线调度——创新点全部可见 |

## 四、必须接受的取舍（游戏方案的前提条件）

### 4.1 砍掉平台跳跃

导师提到的「马里奥闯关类」，**执行上要降级**：

- ❌ 不做：角色跑跳、重力、碰撞、平台地形、手感调试
- ✅ 保留：像素风、关卡地图、逐关解锁、答题即「战斗」、Boss 关、金币 / 经验 / 成就

**理由**：平台跳跃的手感调试会吃掉一半以上开发工时，而团队只有 1 个技术担当。
「闯关感」靠地图推进 + 奖励反馈就能拿到，不必跟物理引擎死磕。

### 4.2 AI 对话的定位：模块，不是主体

- **形态**：游戏内 1 个 NPC（如「口语镇的长老」），点进去聊天练口语
- **第一版能力**：文字对话 + 点击单词发音（TTS），背后接 DeepSeek
- **保底方案**：预置 3–5 段固定对话脚本，API 不通时演示照常进行
- **不做**：语音识别（ASR）坑多，列为加分项

**理由**：把 AI 装进游戏，既保住对话能力，又让整个作品不依赖 API 存活。

## 五、MVP 范围（第一版，务必守死）

| 模块 | 内容 | 优先级 |
|---|---|---|
| 关卡地图 | 3 关，逐关解锁，通关动画 | P0 |
| 答题玩法 | 3 种题型（看词选义 / 听音选词 / 拼写填空） | P0 |
| 词库 | 四级高频前 100 词，分 3 关 | P0 |
| 反馈系统 | 金币、经验、连击、结算页 | P0 |
| 错题本 | 答错自动入本，下次优先复现 | P0 |
| 进度存档 | localStorage，断网可玩 | P0 |
| AI 口语 NPC | 1 个角色，文字对话 + TTS + 固定脚本兜底 | P0（演示版） |
| 艾宾浩斯完整调度 | 完整的间隔重复算法 | P1（写进 PPT 当路线图） |

| 日语词库 | 拓展语种 | P2（本季不做） |

**铁律**：第一版只做 P0。新点子一律进 P1/P2 清单，开发期不加。

## 六、技术选型

- **形态**：单页 H5，手机竖屏优先，PC 端兼容
- **技术栈**：原生 HTML + CSS + JavaScript，**不引入游戏引擎**（团队只有 1 个技术担当，引擎学习成本不如花在体验打磨上；若队友 B 有 Phaser 3 经验再评估）
- **素材**：像素风角色三视图由 AI 生成，先出「主角 1 套 + NPC 2 个」
- **AI 接口**：DeepSeek（文字对话）；TTS 用浏览器原生 `speechSynthesis`，零成本零依赖
- **版本管理**：GitHub，仓库名 `word-quest`

## 八、降级预案（Fallback）

按优先级依次放弃，保证核心可演示：

1. AI 口语 NPC 挂了 → 切固定脚本演示（游戏本体不受影响）
2. TTS 不可用 → 去掉发音按钮，保留文字对话
3. 第 3 关来不及 → 砍到 2 关，保证前 2 关打磨到位
4. 拼写题太难做 → 砍到 2 种题型

**底线**：一个「打得开、玩得完、讲得清」的 2 关游戏 > 一个什么都有的半成品。
