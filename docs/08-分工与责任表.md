# 分工与责任表

> 团队三人**全部零游戏/前端/后端经验**。因此核心原则：**代码由 AI（WorkBuddy）写，人来定方向、供内容、挑毛病。**
> 这条原则让"不会写代码"不再是短板——它正好是 AI 最能补的地方。

---

## 一、三角色一句话定位

| 角色 | 是谁 | 一句话 | 代号 |
|---|---|---|---|
| **组长 / 总指挥** | 你（队长） | 拍板、守范围、验收、对外、写交付物、驱动 AI | 🧭 |
| **内容官** | 队友 A | 游戏的"原料源头"：词、释义、题目、校对 | 📚 |
| **体验官** | 队友 B | 游戏的"用户眼睛"：手机上玩、找 bug、提体验 | 🔍 |
| **编码主力** | AI（WorkBuddy） | 写游戏代码、UI、AI 对话、调研、PRD、原型、素材、PPT、视频 | 🤖 |

---

## 二、逐人责任清单（可勾选）

### 🧭 组长 / 总指挥（你）
- [ ] **拍板决策**：游戏名、MVP 范围、技术取舍，结论写回 `docs/`
- [ ] **守范围**：任何新需求先进 P1/P2 清单，第一版说"不"
- [ ] **对外沟通**：群里拿报名码、确认赛道口径、答疑
- [ ] **验收质量**：每个功能对照 `docs/07` 的验收标准勾选，不达标打回
- [ ] **驱动 AI**：把需求讲清楚，推进开发、调研、PRD、素材、PPT、视频
- [ ] **维护上下文**：决策变了就更新 `AGENTS.md` / `docs/`，保证三人 AI 同频
- [ ] **写交付物**：作品说明、PPT、宣发视频、分工表
- [ ] **红线守护**：11-13 报名、11-24 冻结、不延期

### 📚 内容官（队友 A）
- [ ] 用**表格**整理 100 个四级高频词（单词 / 音标 / 释义 / 1 个例句）
- [ ] 按 3 关难度拆分（每关约 30–35 词）
- [ ] 出 3 种题型素材：选择题、拼写题、听音选词
- [ ] 校对 AI 生成内容**准确性**（释义对不对、例句通不通）
- [ ] 只改 `src/data/` 下的词库文件，不碰其他代码
- [ ] 产出交给 AI 转成游戏可读的 JSON

### 🔍 体验官（队友 B）
- [ ] 每天用**手机**打开当前版本反复玩
- [ ] 记录 bug（什么操作、什么现象、截图）
- [ ] 记录"不爽点"（哪里别扭、看不懂、点不到）
- [ ] 以"小白用户"视角提体验建议
- [ ] **不写代码**，只截图 + 描述问题发群里
- [ ] 验收阶段对照清单点检，签字确认"能玩、不崩"

### 🤖 编码主力（AI / WorkBuddy）
- [ ] 写游戏全部代码（单文件 `index.html` 起步，跑通再拆）
- [ ] 做移动端 H5 布局 + 适配，再做 PC 端
- [ ] 实现出题/判分/进度存档/错题本/艾宾浩斯调度
- [ ] 接入 AI 口语 NPC（文字对话 + 点击发音）
- [ ] 做同类产品调研、PRD、UI 原型、主角三视图素材
- [ ] 生成 PPT（HTML）+ 30–60s 宣发视频
- [ ] 修 bug、按验收标准自检

## 四、协作红线

🔴 **代码只由 AI 写**——成员不要手动改 `index.html` / `src/` 里的逻辑代码，改坏难定位
🔴 **内容官只碰词库 JSON**，体验官只截图不碰代码——避免文件冲突
🔴 **新需求进 P1/P2 清单**，第一版不做（组长负责说"不"）
🔴 **每次开工前 `git pull`**，改完 `add/commit/push`（见 `CONTRIBUTING.md`）

---

## 五、怎么算"各自交付完成"

- 组长：11-13 前报上名 + 11-28 前交齐链接/说明/PPT/视频
- 内容官 A：100 词表 + 3 关题目 + 校对签字
- 体验官 B：每周至少 3 次测玩记录 + 终验签字"能玩不崩"
- AI：每个阶段产出对应文件，且通过 `docs/07` 验收清单

这份表就是三人的"责任状"。谁卡住了，群里喊，一起扛。
