**建议统一成两档，避免后续沟通继续打架**：
- `P0-阻断`：崩溃/白屏/无法继续/数据丢失 → **当前 0 个**。

## 五、架构决策记录（ADR）

### ADR-002：对外入口用「单一正式版」还是「8 版本总览」
- **状态**：Proposed（待队长拍板）
- **Context**：8 版本同台既是资产也是风险。DSH 明确「最该砍」：v0 只有 3 词、对照组属 850 词四档体系、hub 自写「仅内部讨论」，并排会把完整作品稀释成实验记录；每个版本各有声音/文案坑，评委随机点一个就可能看到 404。但 A/B 方法论又是这个作品最硬的答辩证据（4 分 vs 2 分单变量成立）。
- **Options**：
  - **A（推荐）**：对外只给 `game.html`；8 版本总览保留为内部/答辩证据链接，答辩时由队长主动投屏讲解 A/B。
  - **B**：维持总览作对外入口，但给每个版本卡片加「内部实验」灰标 + 状态说明。
  - **C**：另做一页「A/B 证据页」只放 battle-v2 vs 平铺基线两组，其余不展示。
- **Decision**：倾向 A —— 评委的默认路径应是完整作品，A/B 作为「被讲述的证据」而非「自助迷宫」。
- **Consequences**：A 让作品显得更完整、路径唯一；代价是评委不主动看不到 8 版本，需要队长在答辩里主动呈现（可控）。B 保留全部可见但风险最高。C 折中但要多做一页。

### ADR-003：答错反馈「移植肉鸽」还是「上例句卡」
- **状态**：Proposed
- **Context**：豆包建议把肉鸽那套（红框/揭示答案/角色提示）移植进正式版；DSH 建议把现成的例句卡用起来。
- **Options**：
  - **A（推荐）**：例句卡为主 + 保留已有红框/揭示答案，答错延长停留到 ~1.6s 并加一句角色提示。数据 100 词现成，半天可成，直接服务「玩中学 / AI+教学」。
  - **B**：只按豆包移植肉鸽的角色提示层，不上例句。
- **Trade-off**：A 命中教学叙事、投入小；B 情绪反馈更浓但没解决「没学会」的根因。DSH 的诊断更准：缺的不是动画，是**例句从未出现**。
- **Decision**：倾向 A（两者可叠加，但优先级 A > B）。

### ADR-004：改「正式版」与「对照组冻结」铁律的冲突 ⚠️
- **状态**：**BLOCKED — 必须队长拍板**
- **Context**：项目铁律是 **`src/index.html` 作对照组全程不可改**；本次两份反馈的 P0-2 / 例句卡 / T1 喇叭 / 词怪视觉**全都要求改正式版主游戏**。直接改会破坏 A/B 基准与版本对照体系。
- **Options**：
  - **A（推荐，符合既有方法论）**：新建 `game.v3.html`（或 `index.v1.1.html`）承载所有正式版改动，`src/index.html` 原件继续冻结;测试站 `game.html` 指向新版、并保留 `game.v1.html` 作对照。像 v2 一样走「对照组冻结 + 实验组新文件」。
  - **B**：解冻 `src/index.html` 直接改，接受 A/B 基准失效。
  - **C**：先不改正式版，只把改动落在测试站副本，赛后再决定。
- **Trade-off**：A 多一个文件、多一套标签，但保住「从开始到现在全版本可比对」这条你一直坚持的主线；B 最快但会毁掉对照组；C 最保守但上场作品没有改进。
- **Decision**：**需要你一句话确认走 A / B / C**，我才动手。

### ADR-005：`git push` 到公开仓库
- **状态**：待确认（对外动作，不擅自执行）
- **Context**：本地已有 `5011c22` + `9cd57b0`，但从未 push，导致 GitHub 远端与线上站点不同步（DSH P1-11 的观感）。冻结时若要从仓库还原站点会失败。
- **Options**：A 现在 push（含 src/proto、v2、文档、工具）；B 赛后再 push，先本地留档。
- **Trade-off**：A 解决同步风险，但会把未定稿原型公开到仓库；B 保密性好但冻结前必须记得补做。
- **Decision**：需你确认（公开仓库，不擅自推）。
